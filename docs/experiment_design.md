# SIMPLER 재평가 실험 설계

작성 2026-11-18. KSC2026 초안 피드백 3번(통계적 불확실성)과 4번(단계별 지표)에 대응하기 위한 평가 설계.

## 1. 목적

- 과제별 성공률을 지금(과제당 24 에피소드, 1 에피소드 = 4.2%p)보다 정밀하게 추정한다.
- 손 중심(H)과 물체 중심(O), 기준선(E0) 사이의 차이를 **불확실성(신뢰구간)과 함께** 보고한다.
- 학습 반복에 따른 변동을 보고한다.
- 잡기·옮기기 지표의 정의를 명확히 하고, 실패가 어느 단계에서 생기는지 분류한다.

## 2. 고정하는 것

| 항목 | 값 |
|---|---|
| 평가 코드 | 공식 LAPA `46aca51`의 SimplerEnv, `configs/bridge.yaml` (= `lapa_bridge.sh`) |
| 과제 | Bridge 4개: stack_cube, carrot, spoon, eggplant |
| 초기 배치 | 과제마다 공식 24개 전부 (`--obj-episode-range 0 24`) |
| 평가 시드 | **5개 고정: 1234, 1235, 1236, 1237, 1238** (1234는 기존 기본값) |
| 장비 | **새 5090 한 대에서 모든 모델을 평가**. 기존 5090 결과와 섞지 않음 |
| 소프트웨어 | 설치 후 버전 고정, 실행마다 GPU·드라이버·CUDA·jax·sapien 버전과 commit을 결과 폴더에 기록 |

배치를 늘리지 않는 이유: 공식 프로토콜(LAPA 논문 57.3%와 비교 가능)을 유지하기 위해서다.

## 3. 바꾸는 것: 모델

조건 이름은 논문·HF 번호가 서로 달라 혼동되므로 **E0 / O / H**로 부른다.

| 조건 | 의미 | 논문 번호 | HF 이름 |
|---|---|---|---|
| E0 | Stage A 없음 (기준선) | E0 | `e0` |
| O | Stage A = 물체 6칸 (HOT3D 340) | E1 | `e2_340`, `e2_340_s2` |
| H | Stage A = 손목 6칸 (HOT3D 340) | E2 | `e3_340` |

학습 반복은 조건마다 **3회**를 목표로 한다. 학습 코드가 `random.seed(time.time())`를 쓰므로
같은 설정으로 다시 학습하면 서로 독립인 반복이 된다(재현은 안 되므로 체크포인트를 보관한다).

| 조건 | 있는 것 | 추가 학습 |
|---|---|---|
| E0 | 1 (`e0`) | 2 |
| O | 2 (`e2_340`, `e2_340_s2`) | 1 |
| H | 1 (`e3_340`) | 2 |

- `e2_340_s2`가 같은 설정의 재학습인지 확인 필요 (로그상 Stage A 데이터·step 수는 동일).
- 추가 학습 5회 × 약 3시간 (A100 2장, 초안 기준).

## 4. 실행 단위와 규모

실행 1회 = 모델 1개 × 과제 1개 × 시드 1개 = 물건 배치 24개.

| | 모델당 | 1단계 (기존 4개) | 전체 (9개) |
|---|---|---|---|
| 에피소드 | 4 과제 × 24 × 5 = 480 | 1,920 | 4,320 |
| 조건별 과제당 에피소드 | | E0 120 / O 240 / H 120 | 각 360 |

## 5. 평가 코드 변경 (`patches/0001`, 적용: `scripts/apply_patches.sh`)

1. **물건 배치마다 시드 고정** (`--reseed-per-placement`). 공식 코드는 실행 시작에 시드를 한 번만 정하고
   24개 배치가 하나의 난수 흐름을 이어 쓴다. 그러면 배치 k의 난수가 앞 배치들이 쓴 step 수에 따라 달라져서,
   같은 시드라도 모델마다 배치 1~23은 다른 난수로 평가된다.
   패치는 배치 k를 시작할 때마다 난수를 `시드 × 1000 + k`로 다시 정한다. 배치 k의 난수는 (시드, 배치)만으로 정해진다.
   - 모든 모델이 같은 (배치, 시드)에서 같은 난수로 시작한다 → 짝지은 비교
   - 배치 하나만 다시 돌려도 같은 결과 (같은 GPU·소프트웨어 기준) → 실패 분석, 끊긴 실행 재개
   - 행동을 뽑는 방식(샘플링)과 판정 규칙은 그대로다.
2. **배치별 기록** (`--episode-log`): `episodes.jsonl`에 배치 번호, 시드, 성공, 잡기, 옮기기, step 수,
   평가기의 `episode_stats` 전체(연속 잡기, 다른 물체를 옮김 등).
3. (예정) **step 기록**: 그리퍼–물체 최소 거리, 처음 잡은 step, 잡기를 놓친 step. 실패 분류용.

두 옵션은 기본값이 꺼져 있어 넘기지 않으면 공식 동작과 같다. `scripts/eval.py`는 항상 켜서 실행한다.
결과 위치: `results/<model>/<task>/seed<k>/` (`episodes.jsonl`, `env.json`, 공식 출력).

## 6. 지표 정의 (공식 코드 기준, 논문에 명시)

| 지표 | 판정 |
|---|---|
| 성공 | 어느 step에서든 물체가 목표 위에 놓이면 성공, 그 자리에서 에피소드 종료 |
| 잡기 | 에피소드 중 **한 번이라도** 두 손가락이 물체에 접촉 (접촉 힘 방향 60° 이내) |
| 옮기기 | **마지막 step**에 물체가 처음 위치에서 3cm 넘게, 다른 물체보다 많이 움직임. 밀어도 해당 |

세 지표는 순차 단계가 아니다(밀어서 옮기면 잡기 없이 옮기기). 실패 분류는 5번의 step 기록으로 따로 만든다.

| 실패 유형 | 판정 (기준값은 시범 실행 후 확정) |
|---|---|
| 접근 실패 | 그리퍼–물체 최소 거리가 기준 이상 |
| 파지 실패 | 접근했으나 잡기 없음 |
| 운반 실패 | 잡았으나 놓침, 또는 옮기기 없음 |
| 배치 실패 | 옮겼으나 성공 아님 |

## 7. 분석 계획 (결과 보기 전에 고정)

- **결론은 과제별로** 낸다. 4개 과제 평균은 LAPA 관례에 따라 표에 함께 두되 결론 근거로 쓰지 않는다.
- 비교: H − O, H − E0, O − E0. 같은 (물건 배치, 시드) 쌍끼리 짝지어 차이를 계산한다.
- 신뢰구간: 계층 bootstrap 95%. 학습 반복을 먼저 다시 뽑고, 그 안에서 **배치 단위**로 다시 뽑는다
  (같은 배치의 시드 5개는 함께 묶는다). 같은 배치를 반복한 에피소드는 서로 독립이 아니므로
  에피소드 수로 나누는 단순 표준오차는 쓰지 않는다.
- 판정 규칙: 신뢰구간이 0을 포함하지 않으면 "차이가 있다", 포함하면 "현재 결과로는 판단하기 어렵다".
  동등성("유지했다")은 주장하지 않는다.
- 학습 반복별 성공률을 따로 표로 보고한다 (학습 변동).

## 8. 진행 순서

| 단계 | 내용 | 산출 |
|---|---|---|
| 0 | 새 5090에 환경 설치, `env/check_gpu.py` | 버전 기록 |
| 1 | 재현성 확인: 모델 1개, 과제 1개, 시드 1234를 두 번 실행 | 에피소드별 결과가 같은지 |
| 2 | 시간 측정: 실행 1회(24 에피소드) 소요 시간 | 전체 예산 확정 |
| 3 | 기존 체크포인트 4개 × 4 과제 × 시드 5 (80회) | 1단계 결과 |
| 4 | 추가 학습 5회 (A100) — 3단계와 동시 진행 가능 | 체크포인트 |
| 5 | 추가 모델 5개 평가 (100회) | 전체 결과 |
| 6 | 분석, 실패 분류, 논문 수정 | |

1단계에서 같은 시드인데 결과가 다르면(GPU 연산의 비결정성), 시드는 "독립 반복"으로만 해석하고
짝지은 비교 대신 배치 단위 비교만 쓴다.

## 9. 시간 예산 (2단계에서 확정)

step당 0.3~0.5초(7B 추론 + 렌더)로 가정하면 실행 1회는 약 7~12분(eggplant는 최대 120 step이라 약 2배)이다.
모델 1개 × 시드 1개(4 과제, 96 에피소드)는 40~60분, 1단계 80회는 GPU 한 장으로 약 13~20시간,
전체 180회는 약 30~45시간이다. 에피소드가 성공하면 일찍 끝나므로 실제로는 더 짧을 수 있다.
줄여야 하면 **학습 반복 3회는 유지하고 시드를 5 → 3개로** 줄인다.
